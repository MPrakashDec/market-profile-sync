### 1. The "Browser-Heavy" Network Fetching (Huge RAM/CPU Drain)
Currently, `dual_miner.py` keeps the Chromium browsers open for the entire 6+ hour simulation loop, using `page.evaluate(...)` to execute `fetch()` requests from inside the browser context. 
- **The Inefficiency:** Keeping Chromium running continuously per platform consumes massive amounts of RAM and CPU.
- **The Solution:** We only need Playwright for the initial authentication and to intercept the Cloudflare tokens (`j`, `t` for StockMojo, and `token`/`cookies` for StockMock). Once we capture those tokens, we can safely close the browsers and make the API POST requests natively via pure Python using `aiohttp` or `httpx`. This would make the script incredibly lightweight and fast.

### 2. The Global `Semaphore(1)` Choke Point
In the code, you set `mojo_lock = asyncio.Semaphore(1)` and `mock_lock = asyncio.Semaphore(1)`. 
- **The Inefficiency:** While this is extremely safe for rate-limiting, it creates a global bottleneck. If you are mining 8 different dates concurrently, they are all waiting in a single-file line to use that 1 lock. They aren't truly fetching in parallel; they are just taking turns.
- **The Solution:** We can optimize the concurrency limit (e.g., `Semaphore(3)` or `Semaphore(5)`) to fetch multiple dates simultaneously. If we implement a rotating proxy pool, we could remove the semaphore entirely and fetch an entire month of data in minutes.

### 3. Synchronous Disk I/O Blocking the Async Loop
Inside the async `while` loop, the script does synchronous file operations:
```python
with open(raw_file, "a", encoding="utf-8") as raw_f: ...
with open(state_path, "w") as f: ...
```
- **The Inefficiency:** Standard `open()` is blocking. Every time the engine writes the tick data or updates the `live_state.json` dashboard file, the entire `asyncio` event loop freezes while the hard drive spins. Updating `live_state.json` every single minute across multiple dates causes massive disk churn.
- **The Solution:** Use the `aiofiles` library for non-blocking asynchronous disk writes (`async with aiofiles.open(...)`), and "debounce" the dashboard state updates (e.g., only dump `live_state.json` to the disk every 10 ticks, rather than every single minute).

### 4. Premature Data Parsing
For StockMock, we parse the heavily compressed gzip payload immediately into Python dictionaries and then serialize those large matrices into JSON Strings to stream them to the `.jsonl` file. 
- **The Inefficiency:** We are doing heavy CPU work (parsing) in the middle of a network-bound async loop, slowing down the fetch rate. The resulting `.jsonl` file is unnecessarily bloated.
- **The Solution:** Stream the *raw compressed payload* (the base64 gzip string) directly to the `.jsonl` file. Shift all the heavy parsing/decoding logic entirely to the end-of-day Pandas cleanup function.
