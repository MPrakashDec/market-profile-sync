### 1. Does 100MB Instantly Crash Windows?
**No.** On your Dell Latitude (i5 / 8GB RAM), Windows has ~4GB to 5GB of free physical memory when idle. A brief memory spike to 110MB or 120MB will **not** freeze the machine, trigger the OOM (Out-Of-Memory) killer, or crash Windows.

### 2. Why Can RAM Spike for a Single Tick?
In Python, memory spikes happen because of **transient garbage allocation**, not leaks:
- When Fyers sends a full 50-strike option chain snapshot JSON, Python parses a 50KB string into thousands of dicts, lists, and float objects in memory.
- If pandas converts that JSON into a DataFrame or if NumPy computes an array operation, Python requests a block of memory from the Windows OS (via `malloc`).
- Even after the calculation finishes, **Python’s memory allocator does not immediately return that memory to the OS**—it keeps it in an internal pool for reuse. So Task Manager might show RAM jump from 45MB to 85MB or 105MB for a split second.

### 3. What Happens in Our Engine (The Sentinel's Guardrail):
If an engine naively lets memory grow:
- 100MB today $\rightarrow$ 300MB after 4 hours $\rightarrow$ 800MB $\rightarrow$ Windows begins disk paging (swapping to SSD) $\rightarrow$ event loop lags by 500ms $\rightarrow$ WebSocket drops ticks.

To prevent a momentary spike from becoming a permanent leak:
1. **Zero-Spike Invariant:** We do **not** use heavyweight pandas operations inside the 1-second event loop. We use lightweight Python primitives (`dict`, `namedtuple`, `float`, and bounded `collections.deque(maxlen=300)`).
2. **Sentinel Audit Rule:** The Sentinel monitors the process RSS (Resident Set Size).

In short: A single-tick spike is harmless transient noise. The Sentinel only steps in if memory refuses to come back down.
